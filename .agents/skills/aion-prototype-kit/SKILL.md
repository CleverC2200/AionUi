# Aion 轻量业务原型

把业务想法变成一个完整、统一、可点击评审的原型。React、Arco 和构建工具是实现细节，不要求业务人员理解或操作。

## 先通过官方 Skill 能力门

进入任何 UI 制作或样式改造前，检查当前可用 Skills：

1. 已有 `$arco-design`：明确告诉用户“已检测到官方 Arco Skill，本次将按其组件 API 和交互规范执行”，然后加载该 Skill；不能以“已经熟悉 Arco”为由跳过。
2. 没有 `$arco-design`：在本次任务第一次进入 UI 实现前，说明官方 Skill 能提高组件选择和 API 准确性，并询问是否现在安装。等待用户选择，未经同意不得安装。
3. 用户同意安装：使用 `$skill-installer` 从官方仓库 `arco-design/arco-design-skill` 的 `skills/arco-design` 路径安装，并说明新 Skill 从下一轮可用。
4. 用户拒绝或暂不安装：本次任务不再重复询问，改用 [Arco React 官方入门](https://arco.design/react/docs/start) 和当前所需组件文档继续，并在交付说明中注明未使用官方 Skill。

不要把 CLI、Pro、MCP 或其他外部能力与官方组件 Skill 捆绑安装。详细边界见 [delivery-modes.md](references/delivery-modes.md)。

## 先确定交付模式

- **业务评审（默认）**：交付可直接打开的独立 HTML，不依赖开发服务器、登录态或在线 CDN。优先单文件；确需附带资源时，交付 `index.html + assets` 文件夹并说明打开方式。
- **开发接入**：只有用户明确要求接入 AionUi 或其他 React 项目时才启用。遵守目标仓库的组件、i18n、Adapter、测试和构建约定。

目标不明确时采用业务评审模式，并在交付说明中写明这一假设。两种模式的具体边界见 [delivery-modes.md](references/delivery-modes.md)。

## 共同边界

1. 只确认会影响方案的业务事实：谁使用、要完成什么、关键对象与字段、主流程与主动作、重要状态、目标设备和主题。信息足够时直接推进，不把技术栈、YAML 或构建问题交给业务人员。
2. 必须使用 Arco Design React 生成主要交互控件和页面结构，不能只模仿 Arco 外观。同一原型不要混搭其他组件库；只有 Arco 缺少明确业务能力时才增加最小自定义业务块。
3. 实现前建立简短的“业务元素 → Arco 组件”映射，并按需读取 `$arco-design` 中对应组件资料；映射既是实现依据，也是交付证据。
4. 默认推荐红白主题；已有品牌规范或用户指定其他主题时，以其要求为准。旧稿当前颜色本身不等于已确认的品牌规范。成功、警告、错误等状态保留独立语义色，不用品牌红替代全部状态。
5. 在页面显眼位置统一标注模拟边界，不连接真实写接口，不暗示已经完成生产接入。
6. 涉及信息架构、流程步骤、字段含义、权限、计算规则、状态流转、业务能力删减或主次动作变化时，先给出建议和影响，等待用户决定后再实施。
7. 默认只交付一个完整方向。只有用户明确要求方案探索时才制作多个方向，最终仍收敛为一个完整版本。

## 新建原型

1. 用简短业务摘要确认目标、使用者、核心对象、主流程、主动作、关键状态和必要示例数据。未确认的流程步骤、权限、计算规则或状态流转先确认；示例数据和普通文案等非阻塞信息可以使用可见假设。
2. 如果建议会改变信息架构、流程或业务逻辑，先停在建议阶段；否则直接制作。
3. 阅读 [component-rules.md](references/component-rules.md)，业务评审模式从 `assets/review-starter/` 复制最小源码起点，再按组件映射完成一套完整原型；不要从空白 HTML 手写仿 Arco 控件。
4. 按所选交付模式输出，并附三项简短说明：如何打开、哪些内容是模拟、还有哪些假设待确认。

## 改造已有原型

1. 先定位用户指定的旧稿；未提供文件或路径时先索要，不从工作区猜测。读取后列出必须保留的字段、数据、筛选、校验、状态、按钮动作、流程顺序、跳转和存储行为。
2. 默认创建新副本，不覆盖原稿。只替换组件、布局、语义 Token 和反馈样式；尽量保留原有业务函数、状态和事件语义。
3. 遇到依赖 DOM 结构的逻辑时使用窄适配，不操纵 Arco 内部 DOM。无法确认行为是否等价时先说明风险。
4. 将业务改进建议与样式改造分开；未经确认，不把建议混入实现。
5. 交付时提供简短的前后行为对照，说明保留项和已批准的变化。

## 最小验证

业务评审模式先运行轻量检查：

```bash
python3 <skill-dir>/scripts/validate_arco_usage.py <prototype-source> --html <review-html>
```

该脚本只检查真实 Arco 导入、Arco 样式、主要交互是否绕回原生控件、是否混入其他组件库，以及交付 HTML 是否引用在线脚本或样式。它不是产品级质量门禁。

随后实际打开业务评审产物，确认无致命运行错误、主路径和成功/失败反馈可演示、目标宽度无明显页面级横向溢出、没有真实生产请求。已有原型改造还需逐项对照行为清单；交付说明列出本次使用的主要 Arco 组件。

开发接入模式再运行目标仓库要求的定向类型检查、测试或构建；不要把产品级全量门禁加到普通业务评审原型上。
