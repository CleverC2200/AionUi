# Arco 组件与样式规则

只在选择组件、统一视觉或改造已有原型时读取本文件。具体组件 API 必须优先交给 `$arco-design`；只有该 Skill 不可用且用户不安装时才回退到 Arco 官方文档。本文件不复制组件手册。

## 组件选择

- 业务评审原型直接使用 `@arco-design/web-react`；使用 Arco 的 Button、Input、Select、Table、Form、Modal、Drawer、Message 等交互组件，不手写一套“像 Arco”的控件。
- 接入现有项目时，先复用目标项目已有的业务组件或 Arco 封装，再直接使用 Arco 组件。
- 同一原型不混搭其他组件库。Arco 没有对应业务语义时，可以增加一个小型业务组合块，但不要复制基础组件源码或建立第二套组件系统。
- 普通布局和语义容器可以使用原生 HTML；按钮、输入、选择、弹窗等交互控件使用 Arco。

实现前保留一份短映射，例如：

| 业务元素   | Arco 组件                       | 保留的行为                 |
| ---------- | ------------------------------- | -------------------------- |
| 主操作     | `Button type="primary"`         | 原动作、禁用条件和反馈     |
| 查询条件   | `Form`、`Input`、`Select`       | 原字段、默认值和筛选结果   |
| 数据主体   | `Table`                         | 原列、排序、选择和分页语义 |
| 详情与确认 | `Drawer`、`Modal`、`Popconfirm` | 原打开条件和确认结果       |

表格只是格式示例，不要求每个原型使用这些组件；实际映射以业务页面为准。

## 常用页面结构

- 工作台：任务与范围 → 风险或建议 → 筛选 → 数据主体 → 选择范围与动作。
- 表单：任务说明 → 分组字段 → 校验与影响说明 → 主次动作。
- 详情：身份与状态 → 关键指标 → 时间线或版本 → 相关动作。

这些结构是起点，不得为了套模板改变已确认的信息架构或业务流程。

## 主题与反馈

- 无品牌要求时默认推荐红白：红色用于品牌、主操作、当前阶段和选中态；白色或低饱和红灰用于页面与内容面；中性灰用于正文、次要信息和边框。
- 红白是默认方向，不是硬性门禁。已有品牌规范或用户明确指定其他主题时直接覆盖默认值。
- 成功、警告、错误、信息状态使用各自语义色，并配合文字、图标或组件状态表达，不能只靠颜色区分。
- 颜色、间距、圆角、阴影和层级优先使用 Arco Token 或少量语义 CSS 变量；具体色值集中定义，不散落到组件中。
- 每个主要动作都应让用户看见作用范围、进行中状态和成功/失败反馈。

## 已有原型的组件化改造

先建立“现有元素/行为 → Arco 组件”的对应关系，再替换渲染层。字段名、数据结构、校验、计算、权限、状态迁移、事件结果和流程顺序默认保持不变。

如果组件替换会迫使业务行为改变，停止实现并说明：拟改内容、业务影响、保留原样的替代方案。等待用户选择后再继续。
